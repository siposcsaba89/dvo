## Where we are

Pipeline, all offline, the slow part run once:

1. `run_vo` (odometry, rig or stereo) writes per-frame poses (`-o`) and keyframe records (`--keyframes-out`: ORB
   features with depth, affine brightness, hosted map points; format SDVKFR02).
2. `close_loops` works from those exported files only (never rerun odometry for loop / BA / densify experiments):
   loop detection (FBoW, 3D-3D RANSAC, odometry and temporal checks) -> SE3 pose graph -> optional photometric BA
   (`--photometric`) -> optional densify on the final poses over all input frames (`--densify`) -> optional merge of
   duplicate points across passes (`--merge`) -> coloured PLY (`--ply`) and corrected poses (`--out`).

Results:

| | garage (3 fisheyes, 2 laps, 1885 frames) | KITTI 00 (stereo, 4541 frames) |
|---|---|---|
| loops | 88 | 1299, no false ones |
| ATE odometry / pose graph / photometric BA | no GT | 3.95 / 0.893 / 0.948 m |
| photometric BA | 933k residuals, 194k cross-lap, 168 s | 4.29M residuals, 580 s |
| dense cloud | 874k points, 235 s densify | 11.0M points, 1531 s densify |

Feature BA (`--bundle-adjust`) exists but makes KITTI worse; keep it off. Nothing has been compared against COLMAP
yet, and no GS training has been done.

## Step 18: COLMAP-format export for GS / NeuS

Goal: a directory that gsplat (and COLMAP-reading tools) load directly.

- New app `export_scene` (or `close_loops --export DIR`), working from records + corrected poses + rig, like
  `close_loops`.
- **Frames:** every n-th frame or keyframes (option), per camera subset (option; different stride per camera group
  later). Decode from the videos, write `images/<camera>/<frame>.jpg` (or png).
- **Poses:** camera pose = corrected body pose (`--out` of close_loops) x `T_c_b`. COLMAP `images.txt` stores T_c_w
  (quaternion w x y z, translation).
- **Camera model:** EUCM is not a COLMAP model. Fit `OPENCV_FISHEYE` (Kannala-Brandt k1..k4) to each EUCM camera by
  least squares over pixels inside the mask, report the max fit error (target < 0.1 px). Fall back to undistorted
  `PINHOLE` crops if the fit is poor. gsplat reads `OPENCV_FISHEYE` as fisheye (3DGUT handles it). Extend
  `writeColmapText` (currently PINHOLE only) with the model.
- **Points:** `points3D.txt` from the merged dense cloud with voxel thinning (option, e.g. 2-5 cm; KITTI 11M ->
  1-2M), colour, empty tracks (gsplat only needs xyz + rgb). Optional `points3D.ply`.
- **Masks:** `masks/<camera>/<frame>.png` from the camera validity masks (ego vehicle, vignetting). gsplat needs a
  small patch to use them; note it.
- **Exposure:** per-image affine brightness (interpolated between keyframes as in densify) to a side file
  (`exposure.txt`), for an appearance / exposure model in the trainer.
- Tests: KB fit round trip against EUCM (numeric), COLMAP writer round trip, pose convention (a projected point
  lands on the same pixel through the exported model and through `sdv::Camera`).
- Acceptance: gsplat loads the garage and KITTI exports; cameras overlay correctly in its viewer.

## Step 20: per-camera consistency, extrinsic and time-offset refinement

Needed before using more cameras for GS (at the narrow camera 0.1 deg is ~2 px).

- Check: project the dense cloud (or photometric patterns) into every camera with body pose x extrinsic, report
  per-camera photometric rmse / median pixel shift. A camera that is off stands out.
- Refinement: in the photometric BA, optional per-camera `T_c_b` (rig cameras share it over all keyframes; camera 0
  fixed) and a per-camera time offset (pose interpolated along the trajectory velocity). Numeric Jacobian tests.
- Rolling shutter: check the readout time for the wide / narrow cameras; export it for 3DGUT if relevant.

## Step 22: GS training and evaluation (NVIDIA GPU machine, Python allowed there)

- Trainer: **gsplat** (Apache 2.0): COLMAP input, fisheye via 3DGUT, pose optimisation, appearance handling, depth
  loss, 2DGS mode (surfaces, for NeuS comparisons). Quick look without Python: Brush (Apache 2.0).
- Licenses: do not use the original Inria 3DGS or repos built on its rasterizer (2DGS, PGSR, StreetGaussians, ...;
  non-commercial). OpenSplat is AGPL. Verify each license before use.
- Experiments on the same frames, held-out views every 8th frame:
  1. gsplat, fisheyes only, our poses + dense cloud.
  2. Same with gsplat pose optimisation on (shows how much pose error is left).
  3. All 11 cameras.
  4. COLMAP (or GLOMAP) on the same images as the baseline (poses + sparse points), if it succeeds on the garage.
- Metrics: PSNR / SSIM / LPIPS on held-out views, training time, number of Gaussians; for our pipeline also a
  reprojection-consistency metric in pixels (step 20 check).
- Geometry reference: the recording has LiDARs (4x Hesai QT128, Pandar64). Their points (with the sensorconfig
  extrinsics) can measure the accuracy of our dense cloud and of GS depth, and could later supervise depth.

## Step 23: metric monocular depth prior for textureless regions

- Run a commercially usable monocular depth model per exported image: Depth Anything V2 **Small** (Apache 2.0;
  Base/Large are CC-BY-NC), Metric3D v2, MoGe (verify licenses). ONNX Runtime from C++ on this machine, or Python on
  the GS machine.
- Per image: robust scale + shift fit (inverse depth) to our metric points in that image -> metric dense depth.
- Use: extra initial points in textureless areas (floor, road, walls), and a depth loss in gsplat. Compare against
  step 22.
